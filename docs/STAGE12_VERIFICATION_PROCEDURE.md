# 12단계: 1~11단계 정상·금지 요청 실측 대조 절차

이 문서는 시험 실행 절차다. **41종은 모두 미실행**이며 예상 결과를 실제 결과로 옮겨 적지 않는다. 실제 API 요청 없이 통과·실패를 채우지 않는다.

## 표 형식

한 요청당 한 행을 기록한다. 다음 열을 반드시 포함한다.

| 단계 | 시험 ID | 요청 종류 | 실제 요청 경로·방법 | 기대 HTTP·판정 | 실제 HTTP·판정 | 요청 ID | 확인 시각(UTC ISO 8601) | 상태 |
|---|---|---|---|---|---|---|---|---|
| 1~11 | T01~T41 | 정상/금지 | 민감정보 없는 경로·방법 | 사전 정의 | 미실행 | 미발급 | 미확인 | 미실행 |

상태는 미실행 / 실측 통과 / 실측 실패 / 측정 불가 중 하나만 쓴다. 실제 HTTP 응답을 받은 뒤에만 실측 상태로 변경한다. 요청 ID는 응답의 신뢰 가능한 requestId 또는 서버의 추적 ID를 기록한다. 없으면 '미발급'으로 적고 임의 생성한 값을 서버 ID로 표기하지 않는다. 확인 시각은 실제 응답을 받은 시각이다. 응답이 없으면 '미확인'으로 남긴다.

## 41종 시험 준비 및 실행

1. 기존 1~11단계 계약, API 경로, 판정기 규칙, 복구·탐지 문서를 읽고 정상 요청과 금지 요청을 구분하여 T01~T41의 시험 명세를 **실행 전에** 확정한다. 41개 목록이 확인되지 않으면 누락 항목을 임의로 지어내지 말고 '시험 정의 미확인'으로 기록한다.
2. 실제 메모·개인정보 대신 시험 계정과 가상 메모를 사용한다. 비밀번호·Bearer 토큰·기기 증명·본문은 기록하지 않는다. Production의 복구·회수·삭제는 실행하지 않는다.
3. 각 요청을 실제 배포 API로 한 번 보내고, HTTP 상태 코드와 JSON의 판정/오류 코드만 추출한다. 서버 요청 ID 헤더 또는 응답 requestId를 확인하고, 응답 수신 시각을 UTC ISO 8601로 남긴다. 민감한 헤더와 응답 본문은 로그에 남기지 않는다.
4. 정상 요청은 사전에 정한 허용 결과와, 금지 요청은 사전에 정한 거부 결과와 각각 비교한다. 인증 실패나 5xx 응답을 정상 허용의 성공으로 처리하지 않는다. 금지 요청의 네트워크 실패를 정상적인 거부로 처리하지 않는다.
5. 각 실측 행을 저장한 뒤 서버 기록의 요청 ID·시각·HTTP 상태와 대조한다. 불일치 시 '측정 불가' 또는 '실측 실패'로 기록하고 원인 조사 전까지 통과로 바꾸지 않는다.
6. 탈환 작전실의 표와 가린 서버 기록은 동일한 검증된 실측 데이터에서 생성한다. 서버 기록이 아직 없으면 미실행·미확인을 표시한다. 성공률의 분모는 실측한 요청 수와 전체 정의된 시험 수를 별도로 표시한다.

## 판정 조건

정상 요청의 실제 허용과 금지 요청의 실제 거부가 **각각 최소 한 건 이상** 실측되어야 양방향 확인이라고 적을 수 있다. 전체 41종 통과는 사전 정의된 41개 요청 모두가 실제 응답·요청 ID(있을 경우)·확인 시각·기대 결과와 일치한 경우에만 표기한다. 단순 로컬 가상 요청이나 테스트 스크립트의 예상 문자열은 운영 API 실측이 아니다.

현재 결과: 시험 정의 41종의 상세 목록 미제공, 실측 요청 0건, 실측 통과 0건, 양방향 확인 **미실행**.
